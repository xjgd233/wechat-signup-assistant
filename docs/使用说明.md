# 微信活动报名助手

## Mac 上最简单的启动方式

在 Finder 打开这个项目文件夹，双击 **`启动微信报名助手.command`**。首次会自动建立独立环境并安装依赖，之后每次双击即可打开助手；首次安装需要网络。

如果 macOS 阻止打开：在 Finder 里按住 Control 点这个文件，选择“打开”，再在提示框里点“打开”。不要在脚本运行期间把项目文件夹移动位置。

备用终端启动方式：

```bash
python3 wechat_signup_app.py
```

默认操作方式是“我已打开活动详情页”。此模式只操作当前微信窗口，不会唤起、切换或最小化微信。若要用自动搜索，再手动切换到“自动搜索指尖派”。

选择操作方式：

- **自动搜索指尖派**：填写活动标题中的关键词，程序用 OCR 搜索小程序和最相似的活动标题。
- **我已打开活动详情页**：提前在微信打开目标活动，关键词可以留空。

日期默认今天，填写开放时间。点「填入10秒后」可以快速设置测试时间；它只填时间，不会自动开始。选择身份后点「开始等待」。报名按钮由 OCR 识别，OCR 只检查微信窗口区域，不读取助手窗口。角色和报名页确认按钮可以点「校准角色/确认位置」保存相对微信窗口的预设位置；校准时按提示将鼠标放在按钮中心。位置预设保存在 `wechat_signup_app.json`。运行记录保存在 `wechat_signup_app.log`。

首次建议先点「测试识别当前页面」，确认日志能读到微信画面文字。需要授予 macOS「屏幕录制」和「辅助使用」权限。若无法取得微信窗口区域，程序会停止，不会退回全屏识别。

## 极速直点（推荐抢报名时使用）

### 抢的时候怎么点（提前连点 + 失败报告）

「提前 X 秒开始连点「报名」」和「连点 Y 秒仍没进报名页就报告」这两个设置决定了抢的节奏，默认是 **提前 1 秒** 开始、**连点 2 秒** 没成功就报告。

举例：开放时间填 22:40:00，默认设置下程序会在 **22:39:59** 就开始不停点「报名」按钮，大约每秒点 10～20 次；一旦识别到「选择参与角色」页面出现就立刻停手并继续后面的身份、确认、弹窗步骤。如果从 22:39:59 起连点 2 秒（也就是到 22:40:01）还是没进入报名页，程序会弹窗告诉你没抢到，并写明连点次数和耗时，让你能立刻判断是手速问题、名额满了还是按钮位置需要重新校准。

报名按钮的位置来源有两种：校准时保存的「报名按钮」预设，或者「学习我的点击」录下来的第一步。两者都没有时，程序会退回原来的 OCR 找按钮流程（没有连点、也没有这么快的失败报告），所以想抢得动，先把报名按钮的位置准备好。

身份名称必须和微信页面上的文字一致。小程序报名页写的是「参加者」，早期版本的下拉框写作「参与者」，名称不一致会导致 OCR 匹配不到、身份那一步被跳过（最后按小程序默认值提交）。现在下拉框统一为「观摩者 / 参加者」，旧配置里的「参与者」会在启动时自动更正为「参加者」并提示。OCR 找身份时优先精确匹配文字，并在「选择参与角色」标题下方取最上面的那个——选「观摩者」就点上方那个观摩者，选「参加者」就点参加者。

身份这一步在正常（OCR）模式下是**先判断、再决定要不要点**：

* 页面当前选中的身份和你要的一致 → 不点，日志写「当前已经是「参加者」，跳过身份点击」
* 不一致 → 点你要的那个，然后在 2.5 秒内复核它是否真的变成选中状态
* 看不出哪个是选中状态（比如两个都是灰的）→ **停止，不点**，日志说明原因
* 页面上找不到你要的身份按钮 → **停止**，不会盲点，更不会用默认身份提交

判断"哪个是选中"靠的是颜色：选中的按钮是橙色描边浅橙底，未选中是灰字白底。日志里会打出每个身份算出来的"暖色值"（例如 `参加者=164，观摩者=0`），如果哪天阈值不适合你的页面，把日志里这行发我，我按你的实际配色调。

常规流程每一步都用 OCR 找按钮，稳但慢。极速直点模式把「报名按钮 → 身份 → 表单确认 → 弹窗确认」四个位置全部做成相对微信窗口的坐标预设，开放时间一到就按顺序直接连点，完全不跑 OCR，通常比人工还快。

使用步骤：

1. 先把位置预设弄好，两种方式任选：

   **方式一：校准位置。** 在「校准位置」下拉框里选一项（报名按钮 / 身份按钮 / 表单确认 / 弹窗确认 / 全部依次），点「开始校准」，按提示把鼠标停在按钮中心。可以只校准你现在进得去的页面，剩下的以后再补；也可以一次全部依次校准。校准时以**鼠标下面实际压着的那个窗口**作为目标窗口，所以请把鼠标停在指尖派小程序内的按钮上，不要停在助手窗口上。校准完成后程序会记住这个窗口。

   **方式二：学习我的点击（推荐，进不去后面的页面时用这个）。** 点「学习我的点击（手动做一遍）」，然后在指尖派里手动走一遍报名流程，程序会把你点过的位置全部记下来；做完回到助手窗口点「停止学习」。表单页可以点「取消」退出，不会真的报名。之后勾选极速直点，到点就按这个顺序自动回放。这条路径不依赖预设坐标，也不要求你提前进入各个页面。

2. 勾选「极速直点」，并设置「秒/步」的页面切换等待时间（默认 1.0 秒；页面加载慢可加大，追求极限速度可减到 0.3～0.5）。
3. 填好开放时间后点「开始等待」。时间一到即按预设坐标连点，点完请立刻核对微信里的最终结果。

注意：极速直点不做任何 OCR 校验，因此开始前必须确保微信停在活动详情页、窗口大小与校准时一致（位置是相对窗口的，窗口整体移动不影响）。想测试命中效果，可以把活动停在详情页，用「填入10秒后」+ 极速直点试一次，在最终弹窗前手动点「停止」即可。

极速直点的数据来源有两种，程序按这个顺序取用：如果录过「学习我的点击」，就按学习的顺序回放；否则按四个校准位置依次点击（报名 → 身份 → 表单确认 → 弹窗确认）。两边都没有时，程序会拒绝开启极速直点并提示你去补齐。如果四个预设位置几乎完全一样，程序也会拦下来，因为那说明校准时没能切换页面。常规 OCR 模式不受影响。

随时可以点「刷新目标窗口」查看程序当前认定的目标窗口。如果它显示的是微信主窗口（聊天列表）而不是指尖派小程序，说明校准时的鼠标位置不对，重新校准一次即可。微信主窗口和小程序窗口是两个独立窗口，程序只认校准过的那个。

运行时程序会**严格匹配**校准时锁定的那个窗口：窗口 id、进程、标题、尺寸逐级比对，匹配不上就直接停下并告诉你校准时记录的是哪个窗口、现在屏幕上有哪些窗口，不会退回到"随便挑一个微信窗口"——这一点很关键，因为微信主窗口和聊天窗口长得像，认错窗口会点错地方。识别画面也改成了**只抓目标窗口自己的像素**，所以助手窗口就算压在它上面，也不会被拍进画面、更不会被误识别。

## 外观设置

应用图标：橙色圆角方块配一个白色「抢」字，和报名按钮的橙色呼应，中小尺寸下都认得出。图标源文件在项目里：`app_icon.png`（1024 预览）、`app_icon.icns`（macOS 打包用）、`app_icon.ico`（Windows 打包用）。想换一个设计，改 `work/make_icon.py` 里的 `variants` 列表重新跑一次即可（`orange+bolt`、`blue+bolt`、`blue+抢`、`green+tap`、`orange+ring` 都在里面，预览图输出到 `work/icon-preview/`）。

主界面右上角有「设置」按钮，可以调：

* 主题：浅色 / 深色两套预设，切换后仍可逐项微调
* 颜色：强调色、背景色、卡片色、文字色、次要文字色、输入框色（都是取色器）
* 字体：字体族（`auto` 表示跟随系统，Windows 上优先 Segoe UI Variable / 微软雅黑，macOS 上优先 SF Pro / 苹方）、界面字号、日志字号
* 背景图片：选择任意图片作为窗口背景，配合「图片适配方式」和「图片融合强度」调整效果
* 云母背景（仅 Windows 11）：开关 + 通透程度滑块
* 窗口置顶：默认关闭，行为和普通程序一样；需要助手一直浮在最前面时才打开（主界面右上角也有快捷勾选框）

背景图的四种适配方式，选中哪种都不会把图片拉伸变形（除非你主动选“拉伸铺满”）：

| 方式 | 效果 |
| --- | --- |
| 填充裁剪（默认） | 按比例放大到铺满窗口，超出的部分裁掉，比例不变 |
| 完整显示 | 整张图缩放后完整放进窗口，多出来的地方用背景色留边 |
| 拉伸铺满 | 强行拉满窗口，会变形（只有你明确想要时才选） |
| 平铺 | 按图片原始尺寸在窗口里重复排布 |

推荐分辨率：窗口默认是 760×740（接近正方形），所以背景图**用正方形最省心**，推荐 1600×1600 或 2000×2000（高分屏用 2 倍图更清晰）。重要内容放中间，四周留出约 10% 余量——这样即使用「填充裁剪」，窗口比例变化时也不会把主体裁掉。窗口大小可以随意调整，程序每次都会按当前尺寸重新适配。

改完点「应用」立即生效，「保存并关闭」会记住到下次启动。设置存在配置文件的 `ui` 字段里。如果外观被调乱了导致界面不可读，用命令行加 `--reset-ui` 启动一次即可清空外观设置（例：`WeChatSignupAssistant.exe --reset-ui`），业务数据（预设、目标窗口、录制序列）不受影响。

关于云母：Tkinter 没有系统材质接口，无法绘制真正的 Mica 模糊材质。所以这里的实现是——向 Windows 11 的 DWM 申请云母背景（影响标题栏与系统合成），再用窗口通透度实现可调的「半透明」观感。想要系统原生那种毛玻璃，需要换 UI 框架，那是另一个工程量级的事。

界面动效：启动时窗口淡入；主按钮悬停有颜色渐变；开始等待后，执行区右侧出现**倒计时圆环**，越接近开放时间圆环走得越满、中间显示剩余秒数，时间到自动消失。动效都做了失败兜底，旧机器上不支持也不会影响功能。

## 权限（macOS）与备用启动方式

助手需要两项系统权限：**辅助功能**（控制鼠标键盘）和**屏幕录制**（读窗口画面和标题）。没有屏幕录制权限时，macOS 会隐藏所有窗口标题，程序就分不清微信主窗口和小程序窗口。

授权路径：系统设置 → 隐私与安全性 → 辅助功能 / 录屏与系统录音，勾选「微信活动报名助手」。

关键点：**权限只在进程启动时读取一次**，所以开关打开后必须完全退出程序（Command+Q）再重新打开；正在运行的进程不会自动获得新权限。如果开关明明是开的、重启后程序still说未授权，说明那条授权记录对应的是旧版本（每次重新打包签名都会变），需要在那两个列表里选中「微信活动报名助手」按 − 号删掉，重新打开程序并点一次「检查权限」让它重新登记，再把新出现的开关打开，最后再重启一次。

嫌麻烦的话有个更省事的入口：双击项目里的 **`启动助手（终端权限版）.command`**。它用终端来跑助手，而终端通常已经有这两项权限，子进程会直接继承，不用给独立 app 单独授权。它和 app 版本**共用同一份配置**，位置是 `~/Library/Application Support/WeChatSignupAssistant/`，所以校准数据、录制序列两边通用。

如果不使用双击启动器，首次使用前手动安装识别依赖：

```bash
python3 -m pip install -r requirements.txt
```

## Windows EXE

PyInstaller 不能在 macOS 上构建 Windows EXE，需要在 Windows 里打包一次。

步骤：把 `wechat_signup_app.py`、`requirements.txt`、`windows_build.spec`、`build_windows.bat` 四个文件复制到 Windows 10/11（真机或虚拟机都行），安装 Python 3.12（安装时勾选 “Add python.exe to PATH”），双击 `build_windows.bat`。脚本会建好虚拟环境、装依赖、按 `windows_build.spec` 打包。产物在 `dist\WeChatSignupAssistant\WeChatSignupAssistant.exe`，**整个文件夹要一起复制**，不能只拿 exe。

打包完成后先跑一次自检，确认这台 Windows 上各环节都正常：打开命令提示符（Win+R 输入 cmd），进入 `dist\WeChatSignupAssistant` 目录，运行：

```
WeChatSignupAssistant.exe --selftest
```

它会自动检测环境、依赖、剪贴板、窗口枚举、抓图、OCR 中文识别，并把结果写到 exe 同目录的 `selftest_report.txt`，同时弹窗显示摘要。把这份报告发给我，我就能确认 Windows 兼容性、逐条修问题。

Windows 端和 macOS 端的差异：

* 不需要屏幕录制/辅助功能授权（Windows 没有这两个限制），首次运行如果 SmartScreen 拦，点“更多信息 → 仍要运行”。
* 抓图走“截取窗口所在屏幕区域”，所以助手窗口不能压在小程序上面；程序启动抢之前会自动把助手窗口挪到不遮挡的位置，挪不开会在日志里提醒你手动移开。
* 配置和日志就放在 exe 同目录（`wechat_signup_app.json` / `wechat_signup_app.log`），所以**复制整个文件夹就等于复制了一份独立配置**——多开时一个账号一份，互不干扰。

Windows 微信支持多开（重复启动微信进程即可），所以可以在一台 Windows 上同时开多个微信、多个助手副本，每个副本用「选择目标窗口」认领自己那个指尖派窗口。也可以按你原计划，用多个 Windows 虚拟机，一个虚拟机一个账号。
